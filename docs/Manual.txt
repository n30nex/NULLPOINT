NULLPOINT // NATIVE 96K
An original, offline single-player first-person shooter.

RUN
Open NULLPOINT.exe. Press Enter to begin. No installation or downloads.
Requires 64-bit Windows 10/11 and a graphics driver supporting OpenGL 2.1
with framebuffer objects. Only Windows system DLLs are imported.

THE CHALLENGE
The complete playable executable is 95,232 bytes, below both a strict
96,000-byte limit and a 96 KiB limit. It is not an HTML wrapper, launcher,
compressed self-extractor, or downloader. No external game assets are needed.
Source, documentation and preview images are separate optional materials.

MISSION
Explore the reactor facility and sever three power relays with E.
The containment gate opens after all three are offline. Destroy the Warden
and reach the green extraction bay at the far end of its arena.

CONTROLS
W / S        Forward / backward
A / D        Strafe left / right
Mouse        Look (standard, non-inverted)
Left click   Fire
Right click  Aim
1 / 2 / 3    Carbine / shotgun / ion lance
Mouse wheel  Cycle weapons
R            Reload
E            Interact with a nearby relay
Shift        Sprint
Space        Jump
Ctrl         Crouch
Tab (hold)   Facility map
Escape       Pause / resume; releases the mouse
F11          Toggle borderless fullscreen
M            Mute / unmute audio
End          Quit

Arrow keys can aim and F can fire without a mouse.
In the pause menu: Q changes render resolution, minus/plus changes mouse
sensitivity, and N restarts the mission. Alt-Tab automatically pauses.
Choose Recruit, Operative or Veteran with left/right on the title screen.

CONTENTS
Three weapons, three ordinary enemy classes, a six-legged boss, 25 enemies
including relay reinforcements, three relays, pickups, armor, map, jumping,
crouching, sprinting, death/restart and extraction states. Procedural metal
materials, architecture, machinery, animated robots, headlamp shadows,
surface relief, brushed metal, worn paint, damp floors, HDR lighting, soft
bloom, fog, sparks and projectile light. Fans and reactor machinery rotate;
robots have movement-driven strides and death animations, and the Warden
has articulated legs and pistons. Weapons have detailed parts and recoil. Music and
sound effects are synthesized at runtime. Text uses installed Windows fonts.

VERIFICATION
The corrected executable passed 17 gameplay checks, 16 camera-relative WASD
checks (four directions at four headings), four rendered mouse-direction
checks, the OpenGL error check, and animated-combat rendering. A deterministic Recruit playthrough
completed all three relays, defeated all 25 hostiles and extracted through
ordinary movement, firing, damage, pickup and interaction code, without
teleporting or invulnerability. Its perfect aim is not human difficulty QA.

Native 1280x720 render captures were inspected. On the local GTX 1060 6GB,
three 90-frame rendering samples had a median of 3.35 ms/frame, compared
with 4.10 ms/frame for the previous build. These short samples do not
guarantee sustained frame rate on this or other computers.

REPRODUCE CHECKS
From a writable folder, run these optional executable arguments and wait
for the process to exit:
  NULLPOINT.exe --selftest  -> selftest.txt
  NULLPOINT.exe --playtest  -> campaign.txt
  NULLPOINT.exe --verify    -> graphics.txt and six native BMP captures
Exit code zero means the selected check passed. The graphics check requires
a working OpenGL driver. These files are generated only in diagnostic modes.

BUILD
The optional source archive contains nullpoint.c and build.ps1.
With an x86_64 MinGW-w64 GCC on PATH, run build.ps1 in PowerShell. It builds
NULLPOINT.exe beside the source and rejects binaries of 96,000 bytes or more.
An optional -OutputPath argument chooses another output path.
The optimized build uses single-precision geometry, packed model parts,
reused procedural meshes, simpler shader noise and view-based culling.
The verified build used GCC 13.2.0. Other compiler versions may change size.
Do not add -fdata-sections: this linker can put zero-initialized game buffers
in the on-disk data section instead of BSS, unnecessarily increasing size.

CONTROL FIX
Horizontal look, strafing and keyboard yaw now follow the rendered camera's
right/left basis. Both mouse axes and all WASD directions have explicit
rendered-view regression checks.
